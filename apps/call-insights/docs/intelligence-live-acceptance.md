# Intelligence live acceptance

Prepared runner: [`scripts/verify-intelligence.py`](../scripts/verify-intelligence.py). No remote action has been performed by preparing this runner. The profile remains `fevm-serverless-stable-prvwqx`; the deployed app URL must come from the actual Apps deployment.

The runner uses the selected CLI user's token through the HTTPS Apps proxy. It never adds `x-forwarded-*` identity headers, follows login redirects, prints tokens or persists credentials. If programmatic proxy access does not establish `/api/whoami`, use the signed-in app flow and repair the actual OAuth/proxy setup. Do not fabricate proxy identity headers to make a test pass.

Current known source scope is 1,446 historical calls recorded 15 March–2 June 2020. Only 50 calls / 504 turns are completely masked and eligible for classification. A sample can therefore include up to 20 calls; the first full run should include the 50 eligible calls, unless authorized source data changes. No raw-transcript fallback is acceptable.

Run explicit stages using the actual `--app-url https://<verified-host>.databricksapps.com` and a consistent state file. The default state is `/private/tmp/call-insights-intelligence-live.json`; it stores IDs and counts, not tokens or source transcripts. Read-only stages do not require `--execute`. Mutating stages require the flag and persist real workflow records.

1. `--stage preflight`: verifies trusted user/email, Lakebase-backed label listing and app origin. Reopen or repeat this later to establish persistence under the same actor.
2. `--stage sample --execute`: creates a clearly named deployment-verification label over real customer card-replacement requests. Edits it to version 2 and verifies version 1 is unchanged. Confirms a version-2 full run is rejected before a successful version-2 sample, then submits a real sample through the business API. Saves its label, version, run and actual Lakeflow job-run IDs. Does not submit duplicate samples on a normal resumed invocation.
3. `--stage status`: reads named OBO analytics through AppKit's actual SSE contract. Verify pending → running → completed, processed count equals cohort count, no inference errors, and the configured Haiku model is recorded. Partial/failed states remain failures to investigate, never successful negatives. Repeat only when new progress is expected; the runner does not run a polling loop.
4. `--stage evidence --interaction-id <id>`: for a matched/grounded sample result, inspect its authorized masked turns. Check the explicit customer replacement request, the decision, exact quote and original timestamp. Use the app's source link to hear the original moment; verify the return link preserves label and run. The API check alone does not establish audio behavior or model accuracy.
5. `--stage feedback --execute --interaction-id <id> --verdict correct|incorrect --note '<truthful review note>'`: persists an actual reviewed verdict. Choose the verdict after reviewing the source; quote grounding alone does not prove the classification is correct. The status result must show the saved verdict after another request.
6. `--stage full --execute`: requires the same-version successful sample and a saved source-reviewed verdict. Freezes an actual full-cohort preview, records its expiry/count/token estimate, and submits that exact cohort. Estimated prices remain unavailable unless verified model prices were configured. Save and inspect the returned count; the current expected eligible scope is 50, not 1,446.
7. `--stage status`: verify the full run completes, processed/results counts agree with the frozen scope, errors are visible separately, and timestamped quotes are grounded against source turns. Check queue/day/agent prevalence in the app. Close and reopen the app and the exact `/labels/<labelId>?run=<runId>` link; definition, version history, runs and verdicts must persist.
8. Continue through original Call detail to save source transcript evidence into an investigation, reopen it, and verify its original audio timestamp. Evidence-agent acceptance covers case sharing and source permissions. A second restricted identity remains necessary to prove label-result, source and audio isolation.
9. `--stage verify`: reads the persisted definition, both successful runs, the two reviewed sample verdicts, the complete 50-result cohort, library summary and prevalence dimensions again. It asserts the original revision is unchanged and source IDs are unique, then emits compact validation evidence without access tokens or source transcript text. The successful run is saved in [`intelligence-live-validation.json`](intelligence-live-validation.json).

The worker must run as the approved identity with `SELECT, MODIFY` on label runs/results, `SELECT` on snapshots, and query permission on the selected model. It needs no source discovery or Lakebase grant. The app needs its documented mutation permissions and `CAN_MANAGE_RUN` on the bound job. A successful data-owner warehouse smoke test does not establish the worker identity's access; the real sample establishes that execution path.

Automatic tracking, measured business outcomes, typed label-result case attachments, and end-to-end permission isolation are separate acceptance criteria. The runner neither enables nor claims these.
